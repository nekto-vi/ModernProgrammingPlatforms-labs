# Контекст проекта: Туристический GraphQL-агрегатор (Лабораторная работа №5)

## 1. Цель и архитектура проекта
Разработать высокопроизводительное клиент-серверное приложение-агрегатор для путешественников.
- Взаимодействие между фронтендом и бэкендом осуществляется **исключительно через GraphQL** (Query, Mutation, Subscription).
- Архитектура бэкенда: **GraphQL Federation v2** (3 независимых субграфа + единый Apollo Gateway), полностью упакованная в **Docker Compose**.

## 2. Технологический стек (строго придерживаться)
- **Runtime и язык:** Node.js (v20+), TypeScript (или ES Modules JS).
- **GraphQL Backend:** `@apollo/server`, `@apollo/subgraph`, `@apollo/gateway`, `graphql`, `dataloader`, `graphql-subscriptions` (или `graphql-ws`).
- **База данных и ORM:** PostgreSQL 16 + Prisma ORM (или `pg` / `knex`), Redis 7 (`ioredis`) для кэширования и PubSub подписок.
- **Frontend:** React (Vite) + `@apollo/client` + Tailwind CSS (или чистый CSS).
- **Мониторинг и защита:** `@opentelemetry/sdk-node` с экспортом трейсов в Jaeger, `graphql-depth-limit` для защиты от глубоких запросов.

## 3. Источники данных (Доступны из РБ без VPN и ключей)
Приложение собирает данные из 4 открытых источников и хранит более **10 000 записей**:
1. **OpenStreetMap Overpass API** (`https://overpass-api.de`): основной источник (10 000+ записей: музеи, достопримечательности, отели, кафе, парки по крупным городам Европы и СНГ) для наполнения PostgreSQL через фоновый скрипт-парсер.
2. **REST Countries API** (`https://restcountries.com`): справочник стран (код, название, столица, валюта, флаг).
3. **Open-Meteo API** (`https://open-meteo.com`): динамическое получение погоды и прогноза по координатам города (`lat`, `lon`).
4. **Wikipedia REST API** (`https://wikipedia.org{title}`) и **API НБРБ** (`https://nbrb.by`): динамическое обогащение мест описаниями и актуальными курсами валют к BYN.

## 4. Разделение на микросервисы (Subgraphs)
1. **catalog-subgraph:** Работает с PostgreSQL. Отдает сущности `Country`, `City`, `Place`. Реализует сложную фильтрацию, сортировку, полнотекстовый поиск и пагинацию. Обязательно использует `DataLoader` для устранения проблемы N+1 при вложенных связях (`Country -> Cities -> Places`).
2. **external-subgraph:** Расширяет типы `City` (поле `weather`) и `Place` (поля `wikiSummary`, `priceInByn`). Делает HTTP-запросы к внешним API, кэширует ответы в Redis (TTL 30 мин) и реализует отказоустойчивый fallback (при недоступности внешнего API возвращает кэш или `null`, не ломая основной запрос).
3. **reviews-subgraph:** Управляет пользовательскими отзывами, рейтингами и избранным в PostgreSQL. Реализует `Mutation` (добавление отзыва/избранного) и `Subscription` (обновление ленты отзывов в реальном времени через Redis PubSub).
4. **gateway:** Объединяет все три субграфа через `@apollo/gateway` в единую точку входа.

## 5. Правила генерации кода для Copilot
1. Весь проект должен запускаться одной командой `docker-compose up --build`.
2. При написании резолверов всегда учитывай пакетную загрузку (`DataLoader`) и обработку сетевых таймаутов (`AbortController` / `axios` timeout) для внешних API.
3. Соблюдай чистую модульную структуру: отделяй схемы (`schema.graphql`), резолверы, сервисы работы с БД/API и загрузчики данных.
